# 场景模块架构

## 核心原则

将每个已批准动效实现为独立源模块和独立验证单元，同时保持一条统一的 HyperFrames 完整合成。独立的是源代码、数据、时间契约、局部预览和返工范围；默认不把场景预渲染为 MP4、透明 MOV 或 PNG 序列后再拼回成片。

P05 已为每个 Axx 建立独立 `motion-script.md` 和三张用户批准审阅图。P09 的对应模块必须以这四项为实现契约，不得从已废弃的汇总导演脚本反推动效。每个场景 manifest 使用 schema 1.1 引用自身 P05 脚本和三张批准图；旧 schema 1.0 仅用于兼容已冻结项目。

总合成唯一持有连续静音人物视频、标准 MP3、字幕和全局时间；场景模块不得自行播放、暂停、跳转或复制这些媒体。总合成根据绝对时间激活模块，并把局部时间传入模块：

```text
local_time = composition_time - scene_start_time
```

模块内部只使用从 `0` 开始的局部时间。主时间轴整体平移但场景内容不变时，只更新绝对区间；局部动作可以保持不变。

## 目录与契约

P09 使用以下逻辑结构；具体源码扩展名可以服从 HyperFrames 当前版本，但不得把多个无关场景重新塞回一个不可分割文件：

```text
06_hyperframes/src/scenes/
├── scene-module-index.json
├── A01/
│   ├── scene-manifest.json
│   ├── scene source
│   ├── scene data
│   └── preview/
└── A02/...
```

使用 `assets/templates/scene-module-index-template.json` 和 `assets/templates/scene-module-manifest-template.json`。每个 manifest 至少绑定：

- 稳定 A 编号、P04 候选 ID 和 P02 主时间轴片段 ID；
- 成片绝对起止时间与从零开始的局部时长；
- P05 动作时间设计引用；
- P05 对应场景独立动效脚本和三张批准审阅图引用；
- 前一、当前和后一人物状态；
- 入场与出场边界、相邻场景 ID；
- 场景入口、数据文件、隔离预览 composition ID 和共享依赖；
- 用户决定或审批引用；
- 默认完整合成方式及可选独立素材授权。

场景数据优先独立于布局代码。字体、颜色、基础组件、图标系统和转场工具放在共享层；场景模块只声明使用哪些共享依赖，不复制它们。修改共享依赖时必须通过产物依赖图计算所有消费者，不能假称只影响一个场景。

## 隔离预览与完整验证

每个场景必须能在不渲染全片的情况下生成三个局部检查点：入场后、信息最完整时、交接前。隔离预览使用同一场景源码、数据、局部时钟和共享组件，不维护第二套简化实现；三个实现检查点分别与 P05 同角色批准图对照。P05 图片证明用户批准的设计目标，P09 图片证明源码实现结果，二者不是同一文件，也不能互相替代。

隔离预览通过不等于成片通过。修改 Axx 后最低回归范围为：

1. Axx 的结构、时间预算、局部关键帧和隔离预览；
2. 前一场景到 Axx、Axx 到后一场景两个边界；
3. 人物、字幕和同期轨道在真实绝对时间的占用；
4. 被修改共享依赖影响的所有其他场景；
5. 完整合成中的对应时间窗口。

运行：

```text
<python> scripts/validate_scene_modules.py <项目目录> <场景模块索引.json> --implemented
```

验证器检查模块路径、索引顺序、P05 时间契约、绝对/局部时长、人物状态、相邻边界、入口文件和默认合成方式。它不评价视觉内容或用户选择。

## 选择性返工

在产物依赖图中为每个场景模块使用稳定产物 ID，例如 `scene.A01.source`、`scene.A01.data`、`scene.A01.preview`，并登记其对主时间轴、候选矩阵、动作时间设计、用户锁定内容和共享组件的直接依赖。场景修改默认只重建自身，验证两个相邻边界和完整成片对应窗口；只有共享依赖或时间边界变化时才传播到其他场景。
