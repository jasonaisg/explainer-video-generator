# 第一性原理动效拆解规范

## 目的与权威边界

动效不是给口播加装饰，而是降低观众理解成本。先确定认知任务，再选择视觉形式。对主时间轴中的每个语义区间都执行本规范，包括最终不制作动画的区间；不得只分析 Agent 主观上感兴趣的句子。

本规范产生的是制作建议，不是内容权威：

- 五问、评分、阈值和视觉结构建议用于解释 Agent 的制作判断，不得成为内容门禁。
- 用户可以要求制作低分区间、取消高分区间、合并或拆分候选、改变视觉结构或保留纯口播。
- 用户决定写入候选矩阵并成为最终方案；不得用评分否决、拖延或反复挑战用户决定。
- 验证器只检查字段完整、分数范围、合计和阈值建议是否一致，不判断用户选择是否“正确”。

## 分析单位与完整覆盖

先理解完整口播，再以唯一认知任务建立 P04 视觉决策切片，不机械继承 P02 区间或按句号拆分。P02 稳定片段 ID 是覆盖基线和时间锚点，不自动等于 P04 切片；一个 P04 切片可以包含多个连续稳定片段，必要时也可以依据真实字幕时间边界拆分，但不得改变主时间轴、口播顺序或媒体时长。

每个切片都在 `semantic-segmentation.json` 中记录：起止时间、稳定片段 ID、最终字幕 ID、完整转录、唯一认知任务、与前后切片的关系，并回答为什么从这里开始、为什么不能与前段合并、为什么不能在内部继续拆分、为什么在这里结束以及下一段为什么属于新任务。先运行 `<python> scripts/validate_semantic_segmentation.py <语义切片.json>`，通过后才生成候选矩阵。

稳定片段与最终可见字幕是双层权威源：

- 稳定主时间轴决定语义锚点、触发时间和全量覆盖；
- 最终字幕时间轴决定审批页面、V1 字幕和最终可见文字；
- 每个 P04 切片必须分别引用两层 ID，两层均恰好覆盖一次、无遗漏、无重复且顺序一致；
- 不得用主时间轴中可能过期的转录文本重新生成可见字幕。

## 三套完整模式先生成、后推荐

对每个切片先回答基础五问，再分别完成三套可执行方案，最后横向比较并推荐最小充分方案。不得先选推荐类别再补理由，也不得只完整生成推荐类别。

- `V1_PRESENTER_FULL`：连续人物全屏，只显示最终字幕，不添加额外屏幕文字、图标或动画，并说明纯人物表达是否足够。
- `V2_PRESENTER_OVERLAY`：完整记录屏幕文字、最小提示元素、出现顺序、布局、与人脸和字幕的避让、所降低的认知障碍及时间证据。
- `V3_ANIMATION_WITH_PIP`：完整记录主动画信息结构、屏幕文字、变化路径、人物小窗状态与位置、触发点、语义完成点、时间证据和误读控制。

审批界面使用自然语言名称并展示全部方案。用户拒绝推荐时直接选择、修改其他完整方案；不得要求用户从零设计替代方案。

## 两层评价

第一层“视觉必要性”使用理解增益、记忆增益、信息密度、误读风险和制作价值，回答是否值得增加视觉。第二层“模式适配性”分别从认知目标匹配、认知障碍降低、最小充分性、误读控制和时间适配度评价 V1、V2、V3。两层不得混用；评分只解释 Agent 建议，用户最终决定可以覆盖评分。

## 时间轴原生编排

本流程不是根据裸文案估算独立动画时长，而是在已经校正的 P02 主时间轴内编排完整成片。每个区间先定位稳定片段 ID、精确起止时间、视觉触发时间和语义完成时间，再执行五问与评分。不得为了容纳动画而静默改变 MP4、标准 MP3、口播速度、主时间轴零点或句段顺序。

P04 只做区间级判断：

1. 这个认知任务绑定哪些主时间轴片段？
2. 视觉从哪个词或语义事件开始响应，结论何时说完整？
3. 现有区间有多少可用时长？最小结构能否完成？
4. 应采用 V1、V2 还是 V3？与前后人物状态如何交接？
5. 同期存在人物、字幕、动画和哪些其他图层？空间是否可用？
6. 时间可执行性是 `PASS`、`SIMPLIFY`、`MERGE` 还是 `PRESENTER_ONLY`？证据是什么？

P05 再做动作级时间设计：为入场、信息递进、可读停留和退场或交接分配预算。动作预算之和不得超过场景可用时长；不得用负时长、超出主时间轴、无解释重叠或不可读的高速动画满足用户方向。用户要求的视觉在当前区间客观上放不下时，保留用户方向并请用户选择简化、合并相邻区间或修改项目契约；技术不可执行状态未解决前不能伪造为已完成方案。

## 完整成片而非透明素材

第一性原理决定的是完整成片中的信息结构和人物模式，不直接决定独立素材格式：

- `V1_PRESENTER_FULL`：保留连续人物全屏，不制作大型动画；
- `V2_PRESENTER_OVERLAY`：在连续人物画面上使用 HyperFrames 原生标签、箭头、数字或局部图示；
- `V3_ANIMATION_WITH_PIP`：动画成为主画面，同一连续人物视频进入画中画。

默认把 V2/V3 作为 HyperFrames 完整合成中的原生场景和图层，不输出透明 MOV、PNG 序列或供外部剪辑师使用的独立动画。只有用户明确把独立素材列为交付要求时，才能额外生成支持 Alpha 的素材，并记录独立审批引用；该可选交付不得替代完整成片中的同步、人物连续性和场景转场验证。

V3 主动画默认使用平台安全范围内的最大可用画布；人物小窗是画布内叠加元素，不是永久缩小主动画的固定分栏。分别标记平台绝对遮挡区、字幕保护区、人物小窗候选区、主动画可用区和仅供建议的构图区，不得把构图建议误标为绝对禁区。

## 五问模型

对每个语义区间依次回答，不能用分数代替文字论证：

1. **认知目标**：看完这一秒，观众需要新增什么理解？使用可验证的单一结果描述，不写“更有感觉”“更高级”等审美目标。
2. **认知障碍**：信息难在数字抽象、关系复杂、概念易混、步骤过多、条件分支、责任边界，还是容易被忽略？没有明确障碍时如实记录。
3. **视觉优势**：画面能否比纯口播更快、更准地呈现数量、顺序、对照、范围、结构或因果？若答案为否，默认让人物继续口播，不为填满时间轴制造动画。
4. **最小结构**：删除装饰后，完成理解所需的最少元素是什么？先确定信息结构，再决定卡片、图表、路径、物件隐喻或镜头语言。
5. **记忆结果**：如果观众只记住一句话或一个画面，应该是什么？每个区间只允许一个主记忆结果。

## 信息到视觉结构的映射

| 信息本质 | 优先结构 | 不优先 |
|---|---|---|
| 单个关键数字 | 数字计数、比例尺、进度环 | 装饰性粒子堆叠 |
| 两项比较 | 并排卡片、同轴条形、差异高亮 | 两套完全不同的画风 |
| 三项以上比较 | 表格、矩阵、分组列表 | 依次口播式字幕 |
| 操作步骤 | 路径、时间线、流程节点 | 无方向的图标散落 |
| 条件分支 | 决策树、闸门、分流路径 | 把分支画成单线流程 |
| 责任或适用边界 | 容器、内外范围、闸门 | 用模糊渐变表示边界 |
| 算例 | 计算器、分步算式、数值流向 | 只展示最终结果 |
| 分类清单 | 宫格、标签组、层级卡片 | 长段文字 |
| 误区纠正 | 错误命题 → 否定 → 用户锁定的正确命题 | 只打红叉不给解释 |
| 行动清单 | 勾选列表、检查表 | 宣传口号 |

映射是默认建议，不是封闭列表。使用其他结构时说明它为何更符合认知目标，并记录用户最终决定。

## 最小充分原则

- 每个场景只回答一个问题。
- 每个场景最多一个主结论、一个辅助解释和一条主要视觉动作路径。
- 数字必须带单位；比例必须说明用户锁定的基数或适用区间。
- 对比必须使用用户锁定的相同维度和口径。
- 流程必须有方向，分支必须显示条件。
- 算例必须区分演示计算与真实承诺。
- 免责声明必须可读，不能承担纠正主标题错误的任务。
- 人物模式、字幕区、动画区和平台遮挡区共同参与“最小结构”判断；不能只画信息结构而忽略真实合成空间。

## 五维评分标准

每个维度只能取 `0`、`1`、`2`。评分必须附简短证据，不能只填数字。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 理解增益 | 画面不会比口播更清楚 | 画面略微减少理解时间或辅助定位 | 画面显著解释口播难以直接表达的数量、结构、顺序、范围或因果 |
| 记忆增益 | 没有稳定视觉锚点 | 能形成一般性标签或构图记忆 | 能形成与唯一结论强绑定、可复述的视觉锚点 |
| 信息密度 | 主要是情绪、连接或重复表达 | 包含少量并列信息或一个简单关系 | 包含关键数据、多项比较、步骤、分支、算例或复杂边界 |
| 误读风险 | 纯口播已足够明确 | 可能遗漏一个次要条件或关系 | 不可视化就容易误解条件、口径、因果、范围或责任边界 |
| 制作价值 | 制作成本明显高于理解收益 | 收益与成本接近，可合并或简化 | 在可用时长和技术条件内能产生明确理解收益，值得占用成片时间 |

合计 `0–10` 分，机械阈值建议为：

- `7–10`：`PRIORITIZE`，优先制作；
- `4–6`：`MERGE_OR_SIMPLIFY`，与相邻区间合并或使用轻量视觉；
- `0–3`：`PRESENTER_ONLY`，默认保留人物口播。

如果“视觉优势”为否，即使总分较高也要在建议中解释矛盾，默认采用 `PRESENTER_ONLY` 或重新分析区间。阈值建议不能自动成为最终去留；最终去留由用户批准的方案决定。

## 屏幕文案压缩

先写用户锁定的完整事实，再压缩。按以下顺序处理：

1. 删除口头连接词和重复主语；
2. 把并列内容改为标签；
3. 把因果关系改为箭头或路径；
4. 把计算过程改为分步算式；
5. 最后逐项复核所有会改变结论的条件、单位、范围、否定词和责任边界仍然存在。

不得为了简短，把“有机会”“符合条件”“责任范围内”“以正式材料为准”等用户锁定的限定表达改成确定性承诺。任何改写都只是屏幕呈现建议；用户要求使用原文时必须使用原文。

## P04 输出要求

先使用 `assets/templates/semantic-segmentation-template.json` 建立并验证 `semantic-segmentation.json`，再使用 schema 2.0 的 `assets/templates/animation-candidate-matrix-template.json` 建立候选矩阵。schema 1.0 只用于验证已冻结的旧项目，不作为新项目模板。每个切片至少记录：

- 区间 ID、时间范围和转录引用；
- 主时间轴片段 ID、最终字幕引用、视觉触发时间、语义完成时间和可用时长；
- 五问的完整文字答案；
- 信息类型、建议视觉结构和不优先结构；
- 五项分数、逐项证据、总分和机械阈值建议；
- 完整事实、压缩屏幕文字和保留限定项；
- 完整 V1/V2/V3、三种模式的适配评价、Agent 推荐及横向比较理由；
- 用户最终模式、批准方案、结构化决定文件引用及哈希；
- 最终人物模式、画中画与安全区约束；
- 时间可执行性证据、前后人物状态、转场意图和同期轨道；
- 未制作动画时的明确理由。

运行 `<python> scripts/validate_animation_candidates.py <候选矩阵.json>` 检查草案结构，再运行 `<python> scripts/build_p04_review.py <候选矩阵.json> <审批页.html>` 生成无 sandbox iframe 的顶层审批页。交付前实际完成修改、保存、刷新恢复、导出、磁盘读取和正式导入测试。用户决定按以下闭环处理：

```text
审批页 → p04-decisions.json
→ apply_p04_decisions.py <草案矩阵> <决定文件> <最终矩阵> --approval-ref <审批引用>
→ validate_animation_candidates.py <最终矩阵> --final
```

决定文件必须恰好覆盖全部切片、绑定当前矩阵版本与可选 SHA-256，并逐字保留用户输入。应用脚本同步重算当前及相邻人物状态、进出转场、同期轨道、布局约束引用和 `approved_plan`；不能只替换人物模式。最终验证不要求用户决定服从 Agent 评分。

P05 使用 schema 1.1 的 `assets/templates/motion-timing-template.json` 将已批准切片转换为连续 A 编号和动作级预算。每个 Axx 使用 `assets/templates/scene-motion-script-template.md` 建立独立动效脚本，并生成入场构图建立后、信息最完整时、交接前三张真实审阅图；使用 `p05-scene-package-index-template.json` 建立索引。不得再生成汇总性的 `director-motion-script.md`。运行 `<python> scripts/validate_motion_timing.py <动作时间设计.json>` 和 `<python> scripts/validate_p05_scene_packages.py <项目目录> <场景包索引.json> --final`。评分与用户选择属于内容方向；脚本独立性、三图完整性、非负时长、时间边界、预算合计及无解释重叠属于客观执行约束。
