# HyperFrames 制作规范

## 合成结构

以 HTML 为画面源文件。使用一条连续且带 `muted playsinline` 的人物视频，以及一个独立标准 MP3 音频元素。全屏与画中画几何变化必须作用于无定时属性的外层容器；不得改变视频元素尺寸，也不得调用媒体播放方法。按照明确的层叠顺序和安全区，将动画放在人物后方或周围，将字幕放在规定上层。

V2 与 V3 默认是完整 HyperFrames 合成中的原生场景和图层，不是交给外部剪辑软件的透明独立素材。只有项目配置或用户决定明确要求额外独立素材时才渲染 Alpha MOV 或 PNG 序列，并保留相应审批引用；独立素材不能替代完整成片验证。

每个 A 场景必须按[场景模块架构](scene-modules.md)保持源代码与数据独立。总合成以绝对时间激活模块；模块内部只接收局部时间和所需数据，不得拥有或控制媒体播放。隔离预览与完整合成必须复用同一模块实现。

建议逻辑层级：动画与背景、人物容器、局部覆盖层、字幕、诊断层。口播、背景音乐和音效分别使用独立音轨。`data-track-index` 用于避免定时片段冲突，不决定视觉层叠顺序。

## 确定性要求

- 所有暂停状态的 GSAP 时间轴必须同步注册到 `window.__timelines`。
- 时长必须来自 `data-duration`，不得创建空补时动画。
- 禁止使用 `Math.random`、`Date.now`、异步创建时间轴、`repeat:-1`、手动播放或跳转媒体、`data-layer` 和 `data-end`。
- 先用 CSS 构建元素全部可见时的关键帧布局，再使用 `gsap.from` 添加入场动画。
- 不得由相互竞争的时间轴同时改变同一元素的同一属性。
- 需要循环时使用有限次数；需要伪随机时使用固定种子的算法。

## 场景视觉语言

编写任何合成 HTML 前必须先定义 `DESIGN.md`。使用项目明确的颜色、字体、字号层级、动效含义、转场家族、组件和禁止事项。使用适合视频的字号、自然换行和受支持的中文字体回退。不得把中文、数字或表格烘焙到生成式图片中。

所有多场景合成都必须使用统一的转场家族，每个场景元素都要有入场动画。转场承担前一场景的退出交接；除最终场景收尾外，不得在转场前把旧场景元素提前隐藏。第一个动作延后 0.1–0.3 秒，并根据视觉层级改变方向、时长、错落间隔和缓动。

## 字幕

开启字幕时读取已安装的字幕规范。使用真实转录时间戳；同一时刻只显示一组；按安全宽度自适应字号；在每组结束点使用强制 `tl.set` 隐藏。中文或其他非英语音频不得使用 `.en` Whisper 模型。

## 命令执行顺序

1. 从环境报告或项目配置取得已验证的 `<hyperframes>` 调用方式，运行 `doctor` 并记录版本。
2. 验证 P04 候选区间、P05 动作时间设计和场景模块索引，确认所有场景引用同一 P02 主时间轴、预算不越界且绝对/局部时间一致。
3. 使用 HyperFrames `init --non-interactive` 建立工程，不得自行创造不兼容的脚手架。
4. 先编写静态关键帧并生成快照。
5. 添加确定性时间轴。
6. 执行 `lint --json`、`validate --json` 和 `inspect --json`；对密集画面增加采样，并检查转场时间点。
7. 通过 Studio 预览供用户审阅。
8. P08、P10 使用草稿质量；P12 使用高质量渲染。
9. 对真实渲染文件执行 FFprobe 并生成哈希。

以当前机器实际安装版本的 CLI 帮助为准。不得假定操作系统、Shell、包管理器或启动器后缀；自动发现失败时，要求用户提供该机器可执行的 HyperFrames 调用方式，并将其写入项目配置和环境报告。HyperFrames 转录必须分两步：先将媒体转为转录 JSON，再从 JSON 导出 SRT 或 VTT。

## 全屏与画中画连续性

整片只使用一套源时间映射。V3 模式通过外层容器的裁切和 `object-fit`、`object-position` 将现有人物画面放入画中画；每个区间的裁切值保存在数据中。位置、缩放、圆角和裁切形状只作用于外层容器。每次转换前、转换中、转换后都要验证人脸位置，同时检查竖屏平台遮挡区。
