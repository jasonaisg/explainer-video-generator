# 项目契约与目录规范

## 必需输入

1. 已完成剪辑并锁定画面的口播 MP4。
2. 与 MP4 节目音频一致的 MP3。
3. 口播文稿或校正转录稿来源。
4. 用户视频配置文件，其中包含画幅、帧率、动画与字幕安全区、平台遮挡区和交付约束。

可选输入：品牌或设计参考、字幕偏好、外部图片或视频素材、背景音乐、音效、事实依据文件和期望交付版本。

## 规范化配置

原始输入必须保持不变。将配置规范化为 `00_control/project-config.json`，至少包含：

- `source`：路径、哈希、标准音轨、语言和画面锁定状态。
- `video`：宽、高、帧率、时长容差、目标编码和封装格式。
- `safe_areas`：具名矩形或多边形，以及坐标原点。
- `presenter`：人物始终可见、全屏或覆盖或画中画模式、允许的画中画锚点、人脸裁切和对象位置。
- `captions`：是否开启、整句模式、侧车文件、样式和区域。
- `enhancements`：外部素材、背景音乐和音效三个独立开关。
- `approvals`：必须经过的用户审批门。
- `backend`：名称固定为 `hyperframes`；启动器由当前机器探测或由用户显式配置，不得预填开发机器的路径、环境名或平台专用脚本。
- `environment`：记录环境报告位置与自动发现策略。报告可以包含当前机器解析出的绝对路径和版本，但 Skill 模板本身不得硬编码这些值。
- `delivery`：默认带字幕成片，以及用户要求的干净版本。

不得直接从模糊文字中猜测坐标。必须记录规范化解释；如果歧义会影响布局，则必须获得用户审批。

```text
<项目目录>/
├── 00_control/                    # 项目控制面
│   ├── project-config.json        # 规范化配置
│   ├── project-state.json         # 全局状态
│   ├── session-registry.json      # Session 注册表
│   ├── decision-log.md            # 决策日志
│   ├── issue-register.md          # 问题登记册
│   ├── artifact-dependency-graph.json # 产物级依赖图
│   ├── change-control-state.json  # 变更编号与控制状态
│   ├── change-requests/           # CR-xxxx 变更请求与影响分析
│   ├── rework-orders/             # RW-xxxx-xx 选择性返工工单
│   └── approvals/                 # 审批记录
├── 01_inputs/                     # 原始输入或引用
│   ├── video/                     # 口播视频
│   ├── audio/                     # 标准音频
│   ├── script/                    # 文稿
│   ├── config/                    # 原始配置
│   ├── fact-sources/              # 事实依据
│   ├── assets/                    # 外部素材
│   ├── music/                     # 背景音乐
│   └── sfx/                       # 音效
├── 02_media_analysis/             # 媒体探测与同步
├── 03_content_plan/               # 转录、事实与内容方案
├── 04_design/                     # 设计与动效脚本
├── 05_reviews/                    # 审查报告
├── 06_hyperframes/                # HyperFrames 工程
│   ├── src/
│   │   └── scenes/               # Axx 独立源模块、manifest 与模块索引
│   ├── compositions/
│   ├── media/
│   └── data/
├── 07_previews/                   # 审阅图、样片、关键帧和初稿
├── 08_renders/                    # 草稿、成片和变体

├── 10_delivery/                   # 最终交付包
```

大型媒体可以保留在项目外部。记录绝对路径或项目相对引用及 SHA-256；不得只为满足目录形式而复制文件。

每项可被下游消费的冻结产物必须在 `artifact-dependency-graph.json` 中使用稳定 ID 登记直接依赖、版本和 SHA-256。已审批产物的修改必须通过变更请求和选择性返工工单，完整规则见[变更请求、产物依赖图与选择性返工规范](change-control.md)。

## 信息权威顺序

发生冲突时，按以下顺序执行：用户最新明确决定 → 已审批的项目配置或决定记录 → 用户提供的内容与正式依据 → 校正转录稿 → 原始机器转录。Agent 推断、互联网核验、事实判断、措辞建议、审美意见和专业风险意见不属于项目内容权威，只能写入 `content-advice.json` 供用户参考，`gate_effect` 固定为 `NONE`。

用户是全部内容的唯一最终决定者。医疗、法律、金融、保险等主题可以使用用户材料或当前权威来源生成参考核验意见并保留引用，但 Agent 不得据此修改、否决或阻断用户内容。用户拒绝建议后，记录具有约束力的最终决定并继续；项目经理和下游阶段不得重新评判。只有用户尚未作出的必要选择，或能够依据本契约客观复现的输入、文件、媒体、配置、渲染、许可记录和交付故障可以影响门禁。

## 人物画面模式

- `V1_PRESENTER_FULL`：人物占满画面，不出现与人物竞争的大型动画。
- `V2_PRESENTER_OVERLAY`：人物保持全屏，标签或局部图示出现在安全区域。
- `V3_ANIMATION_WITH_PIP`：动画占据信息主画面，同一连续人物视频裁切到圆形画中画中。

对静音视频外层容器做动画，不得改变视频元素尺寸。模式转换前后必须保持源视频时间连续。审批 `presenter-layout-plan` 时，必须包含精确区间、模式、画中画锚点与尺寸及裁切、动画区、字幕区、转场和选择理由。
