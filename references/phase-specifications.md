# 十五阶段执行规范

每个 Session 只读取当前阶段执行卡和其中点名的依赖。每个阶段都必须生成标准五件套交接文件，并把可被下游消费的冻结产物登记到产物依赖图。标有“用户审批”的门禁必须获得用户明确同意，但内容审批仍不等于授权提交。Agent 的所有内容判断只能进入非阻断参考建议；用户决定是下游唯一内容权威。完成用户要求、问答、客观执行修复与自检并冻结最终版本后，必须另行询问用户是否“可以提交项目经理”；只有最新事件为 `SUBMISSION_AUTHORIZED` 才能提交。

## P00 — 初始化项目并冻结输入契约（用户审批）

- 输入：用户需求、所有已知文件路径、项目名称、项目经理 Session 编号和当前约束。
- 动作：初始化目录、状态和注册表；只盘点而不修改输入；记录画面锁定、标准 MP3、人物始终可见、可选模块开关、未知事项和成功定义；起草规范化配置。
- 交付物：输入清单、规范化配置草案、需求与决定记录、能力检查报告、P01 任务包。
- 门禁 G00：每项必需输入均已提供或明确标为待提供；原始文件不可变；用户批准项目范围和配置解释。

## P01 — 校验媒体与同步

- 输入：已批准配置、MP4、MP3。
- 动作：使用 FFprobe 检查流、时长、帧率、分辨率和编码；计算源文件哈希；确认 MP4 有可用画面、MP3 有音频；比较节目开头、结尾和总时长；有疑问时抽查或相关性比较音频；建立零点与容差。不得编辑媒体。
- 交付物：媒体探测 JSON、同步报告、源文件清单、标准时间定义。
- 门禁 G01：媒体可解码；时间轴零点无歧义；差异在配置容差内或已由用户解决；不存在静默变速或偏移。

## P02 — 建立校正转录稿和主时间轴（含义变化时需用户审批）

- 输入：文稿、标准 MP3、G01 时间定义。
- 动作：转录或导入文本；根据文稿和音频校正；保留句子及词或片段时间戳；标记停顿、章节、重音和存疑词；建立单调递增的唯一主时间轴。即使不显示字幕也必须完成本阶段。
- 交付物：原始转录 JSON、校正转录稿、主时间轴 JSON、可选 SRT/VTT 草稿、存疑清单。
- 门禁 G02：起止时间有效且不超出媒体时长；没有重叠或逆序；所有口播区间均已覆盖；会改变含义的存疑词均已解决。

## P03 — 锁定事实与内容

- 输入：校正转录稿、原始文稿、事实依据。
- 动作：提取陈述、数字、单位、名称、日期、条件、比较、例子、免责声明和行动建议；根据用户材料和可用来源生成事实核验参考，但不得自行改变或否决内容；把所有 Agent 内容判断写入 `content-advice.json`，由用户决定是否采纳。
- 交付物：用户内容锁定表、来源登记表、内容到时间轴映射、非阻断事实核验参考、用户最终决定记录。
- 门禁 G03：最终锁定内容与用户最新明确决定一致；参考建议已独立保存且未进入问题门禁；不存在开放的客观执行阻断或未完成用户要求。用户拒绝全部建议时，保持原内容并通过 G03。

## P04 — 筛选动画点并规划人物布局（用户审批）

- 输入：主时间轴、事实锁定表、安全区。
- 动作：逐段回答第一性原理五问；按理解、记忆、密度、误读和制作价值评分；选择最小充分视觉；为每个区间指定 V1、V2 或 V3；定义画中画裁切、锚点和转场；检查人脸、字幕和动画碰撞。
- 交付物：动画候选矩阵、人物布局方案、覆盖关系图、未选动画理由。
- 门禁 G04：每个区间都有明确人物模式；每个动画只有一个认知目标和一个记忆点；安全区通过；用户批准完整方案。

## P05 — 制定视觉、动效、字幕和声音素材方案（用户审批）

- 输入：G04 方案、事实锁定表、可选模块设置、品牌参考。
- 动作：编写 HTML 前先创建 `DESIGN.md`；定义颜色、字体、层级、组件、动效和转场系统；编写带真实时间戳的连续编号动效脚本，明确屏幕文字、图层、入场、停留、转场、画中画、字幕和来源；开启时分别编写字幕、素材和声音方案。
- 交付物：`DESIGN.md`、风格锁定表、导演与动效脚本、字幕方案、素材方案、声音方案、制作清单。
- 门禁 G05：所有场景可执行且确定性；不存在通用默认视觉；每场景一个结论；用户锁定内容、时间和安全区可追溯；用户批准视觉识别和制作方案。

## P06 — 制作前对抗式审查

- 输入：P03–P05 全部产物。
- 动作：从事实、恶意误读和普通理解角度生成非阻断参考建议；从手机可读性、动画可执行性、后期合成、素材许可记录、声音清晰度和 HyperFrames 确定性角度检查是否满足用户技术契约；关闭或重新路由客观执行问题。
- 交付物：脚本对抗式审查报告、修订后产物、问题关闭证据。
- 门禁 G06：开放的客观阻断和未完成用户要求均为零；每个审查角色都有证据或明确说明；内容角色的意见全部保持非阻断。

## P07 — 制作三页代表性静态审阅图（用户审批）

- 输入：已批准的设计与动效方案。
- 动作：用真实文案制作三种关键帧：关键数字或结论；比较或流程或计算；边界或清单或总结。使用真实人物或画中画与字幕区域；测试长文案和平台遮挡压力场景。
- 交付物：三张全分辨率 PNG、总览联系表、布局检查报告、设计调整清单。
- 门禁 G07：视觉系统一致；目标尺寸和手机缩略尺寸均可读；无安全区碰撞；用户批准或给出边界明确的修改意见。

## P08 — 制作真实素材集成样片（用户审批）

- 输入：已批准审阅图、真实 MP4/MP3、一个代表性时间区间。
- 动作：建立 HyperFrames 工程；集成连续静音人物视频、标准音频、人物模式转换、动画、已开启字幕及声音素材；执行 `lint`、`validate`、`inspect`；渲染审阅样片和关键帧。
- 交付物：可编辑样片源工程、样片 MP4、关键帧、CLI 报告、同步证据。
- 门禁 G08：音画同步、人物连续性、动效语言、字幕行为、可选混音和输出质量获得用户批准。

## P09 — 实现全部场景与关键帧

- 输入：锁定的样片系统和完整动效脚本。
- 动作：完成全部合成、组件和数据；保持共享视觉令牌；渲染整片前先生成每个场景的关键帧与转场帧；运行 `lint`、`validate`、`inspect`，可用时运行动画图谱检查。
- 交付物：完整 HyperFrames 源工程、关键帧和联系表、场景覆盖矩阵、技术报告。
- 门禁 G09：每段时间轴均已实现；没有缺失入场或转场；没有开放的客观溢出、对比度或时间故障；屏幕文字与用户锁定内容完全一致。

## P10 — 渲染并审阅全片初稿（用户审批）

- 输入：完整实现工程。
- 动作：使用草稿质量渲染包含已开启模块的整片；检查开头、中段、结尾和每个转场；连续检查同步；在目标画幅和手机尺寸下审阅。
- 交付物：全片初稿、初稿质检报告、带时间戳的用户审阅清单、修改任务书。
- 门禁 G10：用户批准整体内容、节奏、人物布局、字幕和声音素材方向，才可进入精修。

## P11 — 执行受控修改

- 输入：已批准的修改任务书和问题清单。
- 动作：如果属于主流程 G10 修改任务书，在 P11 内将每条需求追溯到源产物和场景；如果属于跨阶段已审批产物变更，必须使用 `CR-xxxx` 和 `RW-xxxx-xx` 机制。只修改工单范围；更新产物节点版本与哈希；对 `VERIFY` 产物执行回归测试；用证据关闭问题。
- 交付物：变更请求引用、返工工单引用、修订源文件和预览、更新后的产物依赖、回归报告、问题关闭表。
- 门禁 G11：所有用户批准修改均已实现；没有开放的客观阻断或未完成用户要求；不存在未授权范围漂移。Agent 建议未被采纳不影响验收。

## P12 — 渲染最终成片

- 输入：通过 G11 的源工程和交付版本矩阵。
- 动作：执行最终严格检查；默认渲染带字幕高质量成片；仅在用户要求时渲染无字幕或不同声音素材版本；保持标准口播不变；存在字幕时生成 SRT/VTT。
- 交付物：最终成片与变体、字幕侧车文件、渲染日志、媒体探测报告、校验值。
- 门禁 G12：编码、分辨率、帧率、时长和音频声道符合配置；文件可解码；同步和安全区通过；文件名与实际版本内容一致。

## P13 — 成片对抗式质检

- 输入：准备交付的真实文件、各类锁定表和清单。
- 动作：抽查每个场景和转场的画面与时间点；逐字核对成片是否忠实执行用户锁定文字、数字和符号；检查黑帧、冻帧、丢帧、截断、字幕强制退场、人物连续性、声音削波与混音、许可记录、命名和可复现性；只修复并重渲染受影响输出。任何新的内容判断只能作为参考建议。
- 交付物：成片对抗式审查、最终技术质检、缺陷证据、发布建议。
- 门禁 G13：开放的客观阻断和未完成用户要求均为零；全部输出忠实执行用户锁定内容，并通过视觉、声音、技术和用户要求的权利记录检查。Agent 对内容的异议不影响门禁。

## P14 — 交付、归档并证明可复现（用户审批）

- 输入：通过 G13 的候选成片和完整项目记录。
- 动作：组装交付目录；包含成片、请求的变体、字幕、可编辑 HyperFrames 工程、配置与数据、事实与风格与动效与人物布局方案、清单、许可、审查和重新渲染命令；验证校验值和路径；记录限制。
- 交付物：交付清单、校验值文件、复现说明、归档报告、最终交接。
- 门禁 G14：用户确认收到文件；清单没有缺失项；新 Agent 能根据记录恢复和重新渲染；项目状态更新为 `COMPLETE`。
