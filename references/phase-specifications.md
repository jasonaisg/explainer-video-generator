# 十五阶段执行规范

每个 Session 只读取当前阶段执行卡和其中点名的依赖。每个阶段都必须生成标准五件套交接文件，并把可被下游消费的冻结产物登记到产物依赖图。标有“用户审批”的门禁必须获得用户明确同意，但内容审批仍不等于授权提交。Agent 的所有内容判断只能进入非阻断参考建议；用户决定是下游唯一内容权威。完成用户要求、问答、客观执行修复与自检并冻结最终版本后，必须另行询问用户是否“可以提交项目经理”；只有最新事件为 `SUBMISSION_AUTHORIZED` 才能提交。

## P00 — 初始化项目并冻结输入契约（用户审批）

- 输入：用户需求、所有已知文件路径、项目名称、项目经理 Session 编号和当前约束。
- 动作：初始化目录、状态和注册表；只盘点而不修改输入；记录画面锁定、标准 MP3、人物始终可见、可选模块开关、未知事项和成功定义；起草规范化配置。
- 交付物：输入清单、规范化配置草案、需求与决定记录、能力检查报告、P01 任务包。
- 门禁 G00：每项必需输入均已提供或明确标为待提供；原始文件不可变；用户批准项目范围和配置解释。

## P01 — 校验媒体与同步

- 输入：已批准配置、MP4、MP3。
- 动作：使用 FFprobe 检查流、时长、帧率、分辨率和编码；计算源文件哈希；确认 MP4 有可用画面、MP3 有音频；比较节目开头、结尾和总时长；有疑问时抽查或相关性比较音频；建立零点与容差。不得编辑媒体。
- 交付物：媒体探测 JSON、同步报告、源文件清单、标准时间定义。
- 门禁 G01：媒体可解码；时间轴零点无歧义；差异在配置容差内或已由用户解决；不存在静默变速或偏移。

## P02 — 建立校正转录稿和主时间轴（含义变化时需用户审批）

- 输入：文稿、标准 MP3、G01 时间定义。
- 动作：转录或导入文本；根据文稿和音频校正；保留句子及词或片段时间戳；为主时间轴每个有效语义片段分配跨下游稳定且唯一的片段 ID；标记停顿、章节、重音和存疑词；建立单调递增的唯一主时间轴。即使不显示字幕也必须完成本阶段。使用 `<python> scripts/validate_timeline.py <主时间轴.json> --kind transcript --duration <总时长秒> --require-ids` 验证主时间轴；原始机器转录和字幕草稿无需伪造稳定 ID。
- 交付物：原始转录 JSON、校正转录稿、带稳定片段 ID 的主时间轴 JSON、可选 SRT/VTT 草稿、存疑清单。
- 门禁 G02：起止时间有效且不超出媒体时长；没有重叠或逆序；主时间轴片段 ID 非空且唯一；所有口播区间均已覆盖；会改变含义的存疑词均已解决。

## P03 — 锁定事实与内容

- 输入：校正转录稿、原始文稿、事实依据。
- 动作：提取陈述、数字、单位、名称、日期、条件、比较、例子、免责声明和行动建议；根据用户材料和可用来源生成事实核验参考，但不得自行改变或否决内容；把所有 Agent 内容判断写入 `content-advice.json`，由用户决定是否采纳。
- 交付物：用户内容锁定表、来源登记表、内容到时间轴映射、非阻断事实核验参考、用户最终决定记录。
- 门禁 G03：最终锁定内容与用户最新明确决定一致；参考建议已独立保存且未进入问题门禁；不存在开放的客观执行阻断或未完成用户要求。用户拒绝全部建议时，保持原内容并通过 G03。

## P04 — 筛选动画点并规划人物布局（用户审批）

- 输入：P02 稳定主时间轴、P02 最终字幕时间轴、P03 用户最终内容决定、项目安全区与平台遮挡配置、人物源片构图证据。
- 动作：完整读取[第一性原理动效拆解规范](first-principles.md)。先理解全文，以唯一认知任务建立 P04 切片并记录边界证据，生成 `semantic-segmentation.json`；稳定 cue 只作为时间与覆盖锚点，最终字幕作为全部可见文字权威。验证两层 ID 均全量一次覆盖。随后为每个切片回答基础五问、完成视觉必要性评分，分别生成完整 V1/V2/V3 方案并做模式适配评价，横向比较后推荐最小充分方案。记录区间级触发点、语义完成点、时间可执行性、人物状态、安全区和同期轨道；V3 主动画使用安全范围内最大画布，人物小窗作为叠加元素。生成顶层交互审批页，真实测试保存、刷新恢复、导出和导入。用户导出的结构化决定必须由 `apply_p04_decisions.py` 正式应用并重算人物邻接、转场与轨道，最后运行 `validate_animation_candidates.py --final`。评分不得阻止用户选择；客观不可执行方案必须简化、合并或走契约变更。
- 交付物：`semantic-segmentation.json`、schema 2.0 动画候选矩阵、稳定 cue 与最终字幕双层覆盖证据、完整 V1/V2/V3 与两层评价、顶层审批页、结构化用户决定 JSON、应用决定后的最终矩阵、人物布局和连续性证据。
- 门禁 G04：切片时间合法且边界证据完整；全部稳定 cue 和最终字幕分别恰好覆盖一次；每个切片只有一个认知任务和记忆结果；V1/V2/V3 均为完整可执行方案且 V1 没有额外屏幕内容；推荐发生在三套方案完成后；用户决定文件完整、唯一、版本与哈希匹配且用户文字未被改写；`approved_plan`、人物邻接、转场和同期轨道与用户最终模式一致；审批页端到端保存和导入测试通过；安全区和区间级时间可执行性通过；用户批准完整方案。最终模式不需要服从 Agent 分数。

## P05 — 制定视觉、动效、字幕和声音素材方案（用户审批）

- 输入：G04 用户批准的最终候选矩阵与人物布局方案、事实锁定表、可选模块设置、品牌参考。
- 动作：编写场景审阅文件前先创建 `DESIGN.md`，定义颜色、字体、层级、组件、动效和转场系统。将 P04 已批准切片按真实绝对时间转换为连续 A 编号；每个 Axx（包括 V1 人物全屏场景）建立独立目录和独立 `motion-script.md`，不得生成或维护汇总性的 `director-motion-script.md`。脚本必须详细说明主动效类别（人物全屏与字幕、卡片、流程图、时间线、对比表、图表、算式、决策树等）、信息结构、真实屏幕文字、视觉风格、人物构图、元素级动画、局部时间、缓动、同期轨道、入场/出场转场、字幕、声音、素材与误读控制。使用 schema 1.1 的 `motion-timing.json` 分配入场、信息递进、可读停留和退出或交接预算，并使每个场景引用自身脚本。为每个 Axx 使用真实内容和最终构图生成恰好三张审阅图：入场构图建立后、信息最完整时、交接前；建立 `scene-package-index.json` 绑定脚本、时间和三张图。按 A 编号逐场景向用户展示三张图及脚本摘要，记录每个场景的批准或修改要求；任何一场未批准都不得视为 P05 内容审阅完成。运行 `validate_motion_timing.py` 和 `validate_p05_scene_packages.py --final`。按照[场景模块架构](scene-modules.md)规划 P09 独立源模块，但 P05 不伪造实现入口。默认制作统一 HyperFrames 成片中的原生 V2/V3 场景；仅在用户明确要求时增加独立透明素材。
- 交付物：`DESIGN.md`、风格锁定表、每个 Axx 的独立动效脚本、每个 Axx 的三张审阅图、场景包索引、动作时间设计 JSON、场景模块规划、逐场景用户审阅记录、字幕方案、素材方案、声音方案、制作清单。`director-motion-script.md` 不属于交付物。
- 门禁 G05：A 编号连续且每个场景都有唯一独立脚本；脚本完整描述类别、结构、风格、元素动作、真实时间、人物、转场和同期轨道；每个场景恰好三张非空、真实内容审阅图并绑定合法的绝对与局部时间；全部场景已由用户逐项批准且有引用；所有动作预算非负且不超过可用时长；不存在越界或无解释重叠；前后人物状态与转场连续；每场景一个结论且内容、安全区可追溯；独立或透明素材仅在有用户要求时出现。

## P06 — 制作前对抗式审查

- 输入：P03–P05 全部产物。
- 动作：从事实、恶意误读和普通理解角度生成非阻断参考建议；从手机可读性、动画可执行性、后期合成、素材许可记录、声音清晰度和 HyperFrames 确定性角度检查是否满足用户技术契约；关闭或重新路由客观执行问题。
- 交付物：脚本对抗式审查报告、修订后产物、问题关闭证据。
- 门禁 G06：开放的客观阻断和未完成用户要求均为零；每个审查角色都有证据或明确说明；内容角色的意见全部保持非阻断。

## P07 — 汇总全场景视觉一致性与压力审阅（用户审批）

- 输入：P05 已逐场景批准的独立动效脚本、每场景三张审阅图、场景包索引和设计系统。
- 动作：不重新替代 P05 的逐场景审阅。汇总全部已批准审阅图形成按时间顺序的联系表，检查跨场景色彩、字体、卡片、图表、人物小窗、字幕保护、视觉密度和转场连续性；选择真实长文案、平台遮挡和高密度场景做手机缩略与安全区压力检查。若需改变单个场景内容，退回原 P05 场景包修改并重新取得该场景批准。
- 交付物：全场景审阅图联系表、跨场景一致性报告、手机与安全区压力检查、必要的 P05 场景返工引用。
- 门禁 G07：P05 每个场景仍保持有效逐场景批准；全片视觉系统一致；目标尺寸和手机缩略尺寸可读；无安全区碰撞；跨场景问题已关闭，用户批准整体一致性。

## P08 — 制作真实素材集成样片（用户审批）

- 输入：已批准审阅图、真实 MP4/MP3、一个代表性时间区间。
- 动作：建立 HyperFrames 工程；集成连续静音人物视频、标准音频、人物模式转换、动画、已开启字幕及声音素材；执行 `lint`、`validate`、`inspect`；渲染审阅样片和关键帧。
- 交付物：可编辑样片源工程、样片 MP4、关键帧、CLI 报告、同步证据。
- 门禁 G08：音画同步、人物连续性、动效语言、字幕行为、可选混音和输出质量获得用户批准。

## P09 — 实现全部场景与关键帧

- 输入：锁定的样片系统和完整动效脚本。
- 动作：完整读取[场景模块架构](scene-modules.md)。以 P05 对应 Axx 的独立动效脚本和三张已批准审阅图为实现契约，把每个 A 编号实现为独立目录、入口、数据和 manifest；场景内部使用从 `0` 开始的局部时间，总合成根据 P05 绝对区间激活模块并唯一持有连续人物视频、标准 MP3 和字幕。共享视觉令牌与基础组件放在共享层，每个模块显式登记依赖。建立 `scene-module-index.json`，运行 `validate_scene_modules.py --implemented`。为每个模块从真实实现渲染入场后、信息最完整和交接前三类隔离关键帧，并逐一对照 P05 同角色批准图；检查两个相邻边界，再运行 HyperFrames `lint`、`validate`、`inspect`，可用时运行动画图谱检查。
- 交付物：模块化 HyperFrames 源工程、场景模块索引与 manifests、场景数据、隔离关键帧和联系表、边界检查、场景覆盖矩阵、技术报告。
- 门禁 G09：每个已批准 A 场景都有独立可验证模块且与 P05 绝对时间和独立脚本一致；三张实现关键帧分别符合 P05 同角色批准图，差异均有明确批准或修复；局部零点为 `0` 且局部时长等于绝对区间时长；入口与数据没有越出自身模块；所有 P05 场景均进入索引；前后边界连续；没有缺失入场或转场；没有开放的客观溢出、对比度或时间故障；屏幕文字与用户锁定内容完全一致。

## P10 — 渲染并审阅全片初稿（用户审批）

- 输入：完整实现工程。
- 动作：使用草稿质量渲染包含已开启模块的整片；检查开头、中段、结尾和每个转场；连续检查同步；在目标画幅和手机尺寸下审阅。
- 交付物：全片初稿、初稿质检报告、带时间戳的用户审阅清单、修改任务书。
- 门禁 G10：用户批准整体内容、节奏、人物布局、字幕和声音素材方向，才可进入精修。

## P11 — 执行受控修改

- 输入：已批准的修改任务书和问题清单。
- 动作：如果属于主流程 G10 修改任务书，在 P11 内将每条需求追溯到具体场景模块、数据或共享依赖；单场景修改默认只重建该模块，验证自身三个检查点、两个相邻边界和成片对应窗口。共享依赖或绝对时间变化时按登记的消费者扩大回归范围。如果属于跨阶段已审批产物变更，必须使用 `CR-xxxx` 和 `RW-xxxx-xx` 机制。只修改工单范围；更新产物节点版本与哈希；对 `VERIFY` 产物执行回归测试；用证据关闭问题。
- 交付物：变更请求引用、返工工单引用、修订源文件和预览、更新后的产物依赖、回归报告、问题关闭表。
- 门禁 G11：所有用户批准修改均已实现；没有开放的客观阻断或未完成用户要求；不存在未授权范围漂移。Agent 建议未被采纳不影响验收。

## P12 — 渲染最终成片

- 输入：通过 G11 的源工程和交付版本矩阵。
- 动作：执行最终严格检查；默认渲染带字幕高质量成片；仅在用户要求时渲染无字幕或不同声音素材版本；保持标准口播不变；存在字幕时生成 SRT/VTT。
- 交付物：最终成片与变体、字幕侧车文件、渲染日志、媒体探测报告、校验值。
- 门禁 G12：编码、分辨率、帧率、时长和音频声道符合配置；文件可解码；同步和安全区通过；文件名与实际版本内容一致。

## P13 — 成片对抗式质检

- 输入：准备交付的真实文件、各类锁定表和清单。
- 动作：抽查每个场景和转场的画面与时间点；逐字核对成片是否忠实执行用户锁定文字、数字和符号；检查黑帧、冻帧、丢帧、截断、字幕强制退场、人物连续性、声音削波与混音、许可记录、命名和可复现性；只修复并重渲染受影响输出。任何新的内容判断只能作为参考建议。
- 交付物：成片对抗式审查、最终技术质检、缺陷证据、发布建议。
- 门禁 G13：开放的客观阻断和未完成用户要求均为零；全部输出忠实执行用户锁定内容，并通过视觉、声音、技术和用户要求的权利记录检查。Agent 对内容的异议不影响门禁。

## P14 — 交付、归档并证明可复现（用户审批）

- 输入：通过 G13 的候选成片和完整项目记录。
- 动作：组装交付目录；包含成片、请求的变体、字幕、可编辑 HyperFrames 工程、配置与数据、事实与风格与动效与人物布局方案、清单、许可、审查和重新渲染命令；验证校验值和路径；记录限制。
- 交付物：交付清单、校验值文件、复现说明、归档报告、最终交接。
- 门禁 G14：用户确认收到文件；清单没有缺失项；新 Agent 能根据记录恢复和重新渲染；项目状态更新为 `COMPLETE`。
